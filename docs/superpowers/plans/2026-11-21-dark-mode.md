# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add the approved site-wide sun/moon toggle.

**Architecture:** Set a root theme attribute before CSS loads, then attach the shared header button after DOM readiness. Add a focused Sass partial for theme surfaces and component overrides without migrating the upstream template.

**Tech Stack:** Jekyll, Liquid, Sass, dependency-free browser JavaScript; Node's built-in test runner for theme behavior.

**Spec:** `docs/superpowers/specs/2026-11-21-dark-mode-design.md`

## Global Constraints

- Preserve existing light appearance, typography, layout, photos, and figures.
- Follow system preference until a manual choice; persist manual choices across visits.
- Apply theme before paint; storage failure must not prevent switching.
- Keep the toggle outside greedy-navigation overflow and available on mobile.
- No frontend framework or runtime dependency; no deployment.
- External frames retain their own appearance; print remains readable on white.

## Review Focus

- Storage access throws: rendering and toggling still work.
- Invalid saved values: fall back to system preference.
- System changes: apply only without a manual override.
- Narrow headers: toggle remains available and navigation still opens.
- Nonstandard layouts: inspect standalone CV and raw HTML pages for theme integration needs.
